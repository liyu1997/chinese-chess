# 高手与宗师引擎说明

## 当前宗师：分阶段快思

2026-11-03 的后续调整取消了宗师每步55秒的等待。现在采用以下时间预算，搜索仍在 Web Worker 中运行：

| 局面 | 单步搜索上限 |
|---|---:|
| 开局：前20半步且至少28子；无历史时用接近初始阵型判断 | 2000毫秒 |
| 常规中局 | 5000毫秒 |
| 非开局将军局面、14子及以下残局 | 7000毫秒 |

上限指引擎计算时间，界面调度和设备负载可能有少量额外延迟。至少完成4层、连续两轮最优着法和评分基本稳定，并达到该阶段预算60%时，可以提前出招；确定杀棋立即返回。时间耗尽只采用最近完整搜索轮次。调用方指定更短的时间上限时，始终遵守更短上限。

高手仍保留8400毫秒上限（原2800毫秒的3倍）。宗师保留12半步常规搜索上限、8半步吃子搜索、180000条置换表和等分最优着法选择；实际完成层数随局面与设备变化。现在不再把宗师描述为“10倍思考预算”，也不宣称棋力保持原55秒版或得到固定倍数提升。

## 提速原理

- 从将帅位置向外查找车炮直线、马腿、兵卒及其他攻击，替代每个候选走法都扫描全盘敌子。保留原规则检测器供普通档位和一致性测试使用。
- 根据棋谱历史、棋子数量及阵型分配时间；撤销和续局也使用同一历史，避免长局面被误判为开局。
- 保留迭代加深、主要变化搜索（PVS）、重复局面的置换表、历史排序和杀手着法。后续候选先快速排除，发现更优变化再完整复查。
- 保留车炮活动、马腿机动、过河兵和将帅防守结构评估；吃子继续推演，被将军时必须搜索合法解将。引擎启动失败明确提示，不降回简单档。

## 实测与验证

同一执行环境、同一局面（红方开局中兵前进一步）、随机源固定0.5，两版都限时2000毫秒的一次对比：

| 指标 | 上一版搜索器限时2秒 | 本版宗师开局 |
|---|---:|---:|
| 实际用时 | 2000毫秒 | 2000毫秒 |
| 完成深度 | 4半步 | 4半步 |
| 搜索节点（含吃子搜索） | 33792 | 75264 |
| 选择着法 | 黑炮移至中路 | 黑炮移至中路 |

本样本节点吞吐约提高2.23倍；节点类型及设备负载影响成本，不能把此数字当成棋力倍数。上一版55秒样本完成6半步，本版2秒完成4半步，说明速度与搜索深度仍有取舍。保留12层上限不等于每步完成12层。

测试覆盖：最多1200半步的两套将军检测及合法走法一致性、陷阱弃车、立即取胜、正确解将、取消搜索、棋盘不变性、阶段预算及Worker消息。运行 `node tests/ai-timing.cjs`、`node tests/ai-strength.cjs`、`node tests/ai-levels.cjs`。全时预算样本：`node tests/ai-benchmark.cjs`。

## 衡量棋力

1. 资源指标：实际用时、节点数、最后完整深度，用于衡量响应与计算效率。
2. 战术指标：固定棋题的正确率与漏算情况，用于衡量搜索质量。
3. 对弈指标：同一时间控制、固定对手、多组开局、交换先后手，统计胜和负与得分率 `(胜 + 0.5×和) / 总局数`，充分样本后再估计相对Elo及置信区间。尚未完成大样本比赛，不宣称人类段位或固定棋力倍数。
